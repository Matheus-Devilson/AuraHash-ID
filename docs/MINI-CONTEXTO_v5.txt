--- VISION DEL PROYECTO ---
AuraHash ID es un protocolo universal de identificacion fisica-digital.
Combina:
- Nucleo: Data Matrix (ISO/IEC 16022) legible por Google Lens, WeChat,
  camaras nativas.
- Seguridad Visual: "Aura Estocastica" (ruido determinista via SHA-256).
- Criptografia: AES-256-GCM + zlib en capas sensibles + firma digital
  Ed25519 end-to-end.
Filosofia: 100% Offline-First. Privacidad por Diseno. Cero dependencia
de servidores en lectura. Codigo abierto (MIT).

--- ARQUITECTURA DE DATOS (3 CAPAS) ---
- capa_publica: JSON MINIFICADO (claves cortas), visible con Google
  Lens. Cero datos sensibles. Contiene el campo "perfil".
- capa_medica: Datos de salud. zlib + AES-256-GCM al vuelo.
- capa_administrativa: Datos legales/financieros. zlib + AES-256-GCM.

--- 4 PERFILES DE APLICACION ---
Formalizados en docs/PERFILES.md. El campo "perfil" va dentro de
capa_publica y se minifica como "p".

1. salud:        Emergencias medicas. PUB + MED + ADM. RBAC futuro.
2. contacto:     Ninos/mascotas/adultos mayores. PUB solo. Cero cripto.
3. verificacion: Boletos/activos con estado. PUB + ADM.
4. legal:        Contratos/certificaciones. PUB + ADM. Firma del emisor.

--- FORMATO DEL PAYLOAD (v3.0.1) ---
PUB:{json_minificado}|MED:AES256GCMZ:{base64}|ADM:AES256GCMZ:{base64}|SHA:{32hex}|SIG:{base64}

Prefijos de cifrado:
- "AES256GCMZ:" -> zlib + AES-256-GCM (formato actual v2.3.0+)
- "AES256GCM:"  -> solo AES-256-GCM (formato legacy v2.1.0)

Mapa de claves cortas PUB (generator.MAPA_CLAVES_PUB):
  perfil->p, tipo->t, instruccion->i, nombre_pila->n,
  alergias_criticas->a, id_visual->v, evento->e

--- HALLAZGOS CRITICOS (LECCIONES APRENDIDAS) ---

1. EL AURA INTERFIERE CON zxing-js.
   - Data Matrix con Aura envolvente: NO legible por zxing-js.
   - Data Matrix con Aura de fondo (opacidad 10%): legible para
     algunos escenarios, no para otros.
   - Data Matrix con Aura de fondo (opacidad 5%): legible para la
     mayoria.
   - Data Matrix SIN Aura: SIEMPRE legible.

2. EL LIMITE DE zxing-js ES ~1500 chars.
   - Data Matrix puro con payload de 789 chars: ✅.
   - Data Matrix puro con payload de 900 chars: ❌ (a veces).
   - Data Matrix puro con payload de 1200 chars: ✅ (a veces).
   - Data Matrix puro con 1500 chars: ❌.
   - El limite real esta entre 900 y 1400 chars.
   - Payloads con secuencias repetidas largas ('XXXX...') confunden
     a zxing-js.

3. EL AURA AYUDA A zxing-js (paradojicamente).
   - Sin Aura (0%): falla para algunos escenarios.
   - Con Aura al 4-5%: funciona para la mayoria.
   - Con Aura al 6-8%: falla.
   - Con Aura al 10%: funciona para algunos.
   - El "punto dulce" es 4-5%.

4. COLISION DE PATRONES DM + AURA.
   - ~30% de los escenarios tienen un Data Matrix cuyo patron
     colisiona con el Aura. Fallan.
   - ~70% funcionan.
   - El patron de fallos cambia con cada regeneracion (con nonce
     aleatorio).
   - Con nonce determinista, el patron de fallos se estabiliza PERO
     sigue habiendo ~30% de fallos.

5. EL NONCE ALEATORIO ERA UN PROBLEMA.
   - Antes: nonce = secrets.token_bytes(12). Cada regeneracion
     producia un Data Matrix diferente. Fallos aleatorios.
   - Ahora: nonce = sha256(id_escenario + '::' + comprimido)[:12].
     Resultado reproducible. Pero los fallos persisten por colision
     de patrones.
